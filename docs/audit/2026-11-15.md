1. **Le script de vérification laisse passer des données qui font planter une page entière** (date `2027-13`, reco sans titre) : la page affiche alors « Impossible de charger la collection ».
2. **La CI ne bloque rien et ne teste pas le code** : `main` n'est pas protégée, et seules les données sont contrôlées (une erreur de syntaxe dans `js/app.js` passerait au vert et serait déployée).
3. **De nombreux petits écarts** entre la doc, le script et le code (champ mal orthographié ignoré en silence, « derniers ajouts » encore annoncé, CSS mort), sans effet visible aujourd'hui.

Bilan : 0 bloquant, 2 importants, 17 mineurs.

## 3. Propositions d'issues (constats importants)

Numéros à confirmer selon le backlog. Aucune n'a été créée.

### BUG-02 — Une donnée non contrôlée fait planter une page entière

- Labels proposés : `type:bug`, `epic:socle`, `prio:should`, `pts:3`
- Problème : le script de vérification accepte une date `a_paraitre` au mois invalide et des recos sans `titre`, `auteurs` ou `tomes_parus` ; le site remplace alors toute la page par « Impossible de charger la collection » (constats 1, 3 et 13).
- Critères d'acceptance :
  - [ ] Le script refuse un mois hors de 01 à 12 dans une date `a_paraitre`.
  - [ ] Le script contrôle dans `reco.json` : `titre` (texte non vide), `auteurs` (liste non vide), `editeur`, `tomes_parus` (entier ≥ 1), `parution`.
  - [ ] Le script exige `https://` pour toutes les `sources` (recos et `a_paraitre`).
  - [ ] Une donnée inattendue dans un encart ne fait plus tomber toute la page, et le message distingue « données illisibles » de « erreur d'affichage ».
  - [ ] En cas d'erreur, l'en-tête n'affiche plus « Chargement… ».
  - [ ] `python3 scripts/verifier_donnees.py` passe toujours sur les données actuelles.
- Fichiers pressentis : `scripts/verifier_donnees.py`, `js/app.js`

### OPT-04 — La CI ne contrôle pas le code du site et ne bloque pas la fusion

- Labels proposés : `type:opt`, `epic:socle`, `prio:should`, `pts:2`, `needs-validation`
- Problème : l'Action ne vérifie que `data/` et les `?v=N` ; `main` n'est pas protégée (constats 2 et 9). La protection de branche est un réglage du repo, donc une décision du PO.
- Critères d'acceptance :
  - [ ] L'Action vérifie la syntaxe de `js/app.js` (par exemple `node --check`, déjà présent sur les runners, sans dépendance à installer).
  - [ ] L'Action échoue si `js/app.js` ou `css/style.css` diffère de `main` sans que N ait augmenté.
  - [ ] Décision du PO sur la protection de `main` (contrôle requis avant fusion), appliquée ou écartée en connaissance de cause.
  - [ ] La ligne de la DoD sur `?v=N` décrit ce qui est réellement contrôlé.
- Fichiers pressentis : `.github/workflows/verifier-donnees.yml`, `scripts/verifier_donnees.py`, `.github/pull_request_template.md`, `CLAUDE.md`
